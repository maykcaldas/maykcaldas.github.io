# Mayk Caldas’s personal website

A React + TypeScript website built with Vite. The current cream-and-purple design, logo, content, public asset URLs, and four main routes are preserved:

- `/` — biography, selected research, writing, and contact.
- `/academic/` — publications, research, education, and talks.
- `/developer/` — scientific software, repositories, and live project links.
- `/blog/` — Markdown posts, each with its own page.

## Run it locally

Use Node.js 24 LTS (minimum 22.12) and npm:

```sh
npm ci
npm run dev
```

Open **http://127.0.0.1:5173/**. Vite reloads React, TypeScript, CSS, and Markdown changes during development.

To check the production output, including real directory URLs, RSS, sitemap, compatibility redirects, and 404 responses:

```sh
npm run check
npm run preview
```

Open **http://127.0.0.1:4173/**. Both servers bind to localhost. Use `PORT=4174 npm run preview` for another preview port.

## How the application works

React components describe the interface. Shared components receive typed props; the filter component owns its query and topic with `useState`. The theme button updates the document theme and persists it when browser storage is available.

At build time, Markdown becomes sanitized HTML and React renders every known route to HTML. In the browser, `hydrateRoot` attaches React behavior to that existing content. The site uses ordinary page links, so navigation works with GitHub Pages and content remains readable without JavaScript. It needs no production Node server or catch-all routing rule.

The only `dangerouslySetInnerHTML` boundary is the article body, sanitized during generation. Publication and project content is normal JSX. React 19 automatically emits preload hints for important images.

Useful references: [React hydration](https://react.dev/reference/react-dom/client/hydrateRoot) and [Vite static deployment](https://vite.dev/guide/static-deploy.html).

## Updating content and design

Add publications or projects in `src/content/data.ts`, following the interfaces in `src/content/types.ts`. Project `paper` values refer to publication IDs; keep these stable for bookmarks.

For a post, add a Markdown file to `content/posts/` and an entry to `content/posts/index.json`:

```json
{
  "title": "A question worth exploring",
  "date": "2026-10-05",
  "tags": ["chemistry", "learning"],
  "file": "a-question-worth-exploring.md"
}
```

The filename produces `/blog/a-question-worth-exploring/`. The index is authoritative for metadata; optional Markdown front matter is stripped. Removing an index entry and rebuilding removes its generated page automatically. RSS and sitemap follow the same content index. Those production artifacts are generated by `npm run build`, not the development server.

All content committed to this public repository is public. Keep private writing outside the repository until a separately authenticated publishing system exists.

Change colors and spacing in `src/styles/site.css`. The editable SVG monogram and logo are in `public/assets/brand/`, with the simplified favicon at `public/assets/favicon.svg`. Header and footer use CSS masks so the same vector works in both themes. These vectors reconstruct the supplied raster logo; they are not the original designer’s source files.

## Verification

- `npm run typecheck` generates content and checks all TypeScript, including scripts and tests.
- `npm test` checks search/topic combinations, empty states, filtered anchors, theme persistence, legacy routes, and Markdown sanitization.
- `npm run check` also builds the site and checks every generated page’s metadata, IDs, internal links, assets, anchors, content, RSS, and sitemap.

The test worker disables Node’s experimental Web Storage API so JSDOM provides browser storage consistently on Node 25 as well as LTS releases.

## Reading the code

Start with `src/pages/Home.tsx`: it reads content data and describes the homepage as nested JSX. The section comments follow the visible page order. Follow a component import into `src/components/` to see how shared pieces work; props are the values passed into them.

### Composing pages from components

Pages choose content and section order. Components own the reusable markup and styling hooks. For example, Home and Teaching both use `LinkCard`; Academic uses `TimelineEntry` for both education and talks.

| Component | Responsibility |
| --- | --- |
| `SectionHeading` | Section title and optional action or label beside it |
| `LinkCard` | A whole-card link with a title, description, and call to action |
| `TimelineEntry` | Date and title layout with custom details supplied as children |
| `PublicationRow` | Publication image, authors, venue, and paper/code links |
| `ResearchCard` | Compact publication presentation for featured research |
| `ProjectCard` | Project image, description, tags, and links |
| `Toolkit` | Named tool groups with icons |

Props describe the varying content. `children` supplies a nested piece of JSX where the structure needs flexibility:

```tsx
<SectionHeading
  title="From papers to tools."
  actions={<TextLink href="/developer/">Explore the software</TextLink>}
/>

<TimelineEntry period="2024" title="Summer school">
  <p>Teaching materials and practical exercises.</p>
</TimelineEntry>
```

`LinkCard` accepts `headingLevel` so it can preserve the correct heading hierarchy in each page. These components do not introduce extra wrapper elements, which keeps the existing CSS layouts intact. Distinctive sections such as the homepage portrait remain in their page until there is a useful reason to share them.

For the build, read `package.json` first, then follow these scripts:

1. `scripts/generate-content.ts` calls `generateContent()`.
2. `scripts/content.ts` validates post metadata, prepares Markdown, creates excerpts, and writes the generated content file. Each step has a named helper.
3. Vite builds the browser assets using `vite.config.ts`.
4. `scripts/prerender.tsx` adds metadata and rendered React content to each page, then writes the sitemap and RSS feed.
5. `scripts/preview.ts` serves those finished files locally when you run `npm run preview`.

The source uses two-space indentation, single quotes in TypeScript, and expanded JSX and CSS blocks. Keep related code together, and use comments to explain intent rather than restating individual lines.

## Learning exercises

1. Read `src/pages/Home.tsx` alongside the homepage; identify components, props, and JSX.
2. Add a project through its TypeScript interface, then deliberately omit a required field to see a compiler error.
3. Follow `FilterList.tsx`: input event → state update → filtered render. Add a sort control as a separate state value.
4. Add a Markdown post and trace generation, React rendering, and hydration.
5. Extract another repeated UI pattern into a component with typed props.
6. Add an interactive experiment using React state and link it from Developer.
7. Later, connect an experiment to a separately hosted backend to learn HTTP APIs and CORS.

## Temporarily hidden blog

`src/content/settings.ts` sets `blogEnabled` to `false`. This hides navigation, the homepage card and recent posts, blog and legacy post routes, and RSS output. Draft text is excluded from generated browser content. All blog components, scripts, and Markdown files remain in the repository. To restore the blog, review the drafts in `content/posts/index.json`, set `blogEnabled` to `true`, and rebuild. Restart the development server after changing this build setting. The drafts remain visible to anyone with access to the repository; this setting only controls the built website.
